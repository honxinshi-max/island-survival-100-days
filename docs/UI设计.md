# UI 设计

## 1. 设计目标

UI 的首要任务不是展示世界观，而是让 3—5 人在每个决策时刻看清：现在能做什么、要付什么、何时结算、失败会失去什么、这一步是否锁死百日救援路线。桌面卡牌原型和数字实现应共享同一信息架构。

## 2. 主界面信息层级

### 顶部：时间与全局风险

- 当前天数、白天/夜间、信标当前状态（含停机/已摧毁）与按连续广播数重算的最迟有效广播日；
- 普通事件/危机模块的“可用/缺源停用”状态；合法预告必须同时显示来源能力、精度和失效时点，无来源时显示“无公开预告”；
- 天气 W、岛屿特性、难度倍率；
- 团队从当日至终局夜是否仍满足四账可胜性；材料、行动、生存、能源/可达分别显示“通过/无效/待确认”，并可附非泄密缺口类别，不得把缺失数据画成通过。

### 左侧：角色区

每名角色显示生命、行动点、已预支行动、饱腹、水分、体温、伤势、疾病、装备耐久和职业能力。状态悬停或展开后必须显示下一结算时点与具体后果，不能只用颜色。

### 中央：岛屿与行动区

- 区域连接、当前角色位置、移动成本、已发现/未发现状态；
- 只对已发现资源点显示当前/初始储量、恢复类别和下次恢复日；未发现点的位置与储量不得出现在玩家视图；
- 可执行行动卡必须同时显示行动点、工具耐久、目标值、材料、预期进度和失败损失；
- 禁用行动保留可见，并给出唯一主因和所有次因。

### 右侧：营地与项目区

- 建筑按完好/受损/停机显示，不只显示耐久数字；
- 当日可用能源、跨夜保留上限、已登记设备及占用原因、今夜能源承诺；
- 项目材料是否已支付、当前里程碑、该段难度、进度和取消返还；
- 信标五段不得把跨段进度画成连续无边界进度条；行动预算必须显示逐段 `ceil（进度÷2）` 后的合计。

### 底部：决策与日志

- 当前检定公式和每个加减值来源；
- 结果等级、进度、消耗、耐久和状态变化；
- 可展开的夜间 7 步日志；
- 撤销只允许在尚未揭示随机结果、未影响其他玩家信息时使用。

## 3. 关键流程

### 日间计划

团队先看“必须支付”清单，再分配角色行动。系统应提示材料够但行动/能源/路线不够的假可行方案，不能只检查背包材料。

### 项目检定

确认框依次展示：当前里程碑 → 目标值 → 执行者/协助者各自行动成本 → 首次掷骰前支付的材料与样本 → 可能进度。若本次进度超过段需求，V1.3.1 明确提示“超出部分丢弃、不结转”。

### 夜间结算

按固定 7 步逐项动画/卡牌结算。普通事件模块通过源闭合门时，第 1 步内部依次为“自动防御能源承诺 → 普通事件 → 已取得的危机预防 → 保留危机的应对/止损 → 其余营地防御战”；模块缺源时明确跳过普通事件槽，不允许主持人临时补牌。灾害摧毁发电设备后，信标广播失败必须引用同夜第 1 步的具体原因。

### 濒死救治

清晨界面按“状态结算 → 行动计算 → 紧急救治 → 死亡 → 资源恢复 → 建筑产出 → 驯兽处理”显示队列；剩余 0 天疾病须显示“待到期：本晨最后一次效果”，战斗来源的濒死者也进入同一救治列表。救治面板要显示每名救治者是否已用预支救治、当日剩余行动和未救治角色的死亡时点，禁止同一行动点被多次选择；缺源的重伤检定不得出现按钮。

### 终局结算

第 100/20 夜在夜间第 1—6 步后进入单独的“终局健康闭合”画面，只显示状态伤害、紧急救治、死亡和一次性胜负判定。界面不得生成第 101/21 天的资源或建筑产出，也不得提供继续建造、治疗或广播来改判的按钮。

## 4. 信息公开边界

- 开局公开规则版本、模式、难度、玩家数/职业、当前天数和已揭示岛屿特性；
- 未发现点、全图评分分母、四账隐藏保证路线及未来事件牌序只在主持审计视图可见；
- 四账玩家视图只显示“通过/无效/待确认”和非泄密缺口类别，不显示隐藏资源来源；
- 预知能力只揭示其明文允许的字段，并显示来源、精度和期限；
- 事件/危机正式揭示后，选择成本、目标值、全部结果带、最终权重、候选表、抽取结果和最终标签进入公开日志；
- 当前事件卡表未入库，因此界面必须显示“普通事件：缺源停用”，不得显示主持人自编内容。

## 5. 可访问性

- 状态不能只依赖红/绿；同时用文字、图标和纹理。
- 全部操作可由键盘/手柄到达；焦点顺序与日间计划顺序一致。
- 骰点和状态变化提供文本日志，屏幕阅读器只播报变化，不逐帧重播。
- 可关闭摇晃、闪烁和高频音效；危机倒计时不只靠声音。
- 关键数值使用可缩放字体；四人角色区在窄屏改为分页，不压缩到不可读。

## 6. 试玩数据面板

每局必须记录规则版本、模式、难度、人数/职业、地图配置 ID 或种子、岛屿特性、事件序列、危机 ID/等级/来源/最终标签和终局结果；只有版本、模式、难度相同的样本才能合并计算胜率。

首次稳定饮水/食物日统一使用连续 3 天无随机投影；第三天中断时不得提前记为稳定。每次已消费日常行动必须且只能归入：移动、采集、加工/制造、研究、建造、维修/维护、治疗/休息、设备操作、战斗、协助、其他。行动占比的分母必须是全部标签之和，失败行动和预支救治也计入。

“没有真实选择”记录 0 个或更多时刻，不强迫填写三个；每项记录当时状态、公开选项、玩家认为可行的选项、实际选择与即时后果。面板展示原始数，不自动把相关性写成因果。

## 7. 验收标准

- 玩家无需查规则书即可解释为什么行动不可用或为何广播中断；
- 任意项目都能追溯材料、行动、检定和进度；
- 资源点 0 与 1 不形成隐藏规则套利；
- 建筑 1 耐久不会看起来与满耐久同效；
- 最终校准至少显示并结算一次难度 11 检定；
- 项目第一次失败不能回滚为未支付材料，协助者的行动必须进入日志；
- 受损基础效果 1 显示为 0，二元能力显示“受损不可用”或卡牌覆盖来源；
- 评分使用全图可再生点分母，未探索点不能从分母消失；
- 玩家视图不能看到未发现点、全图分母、隐藏保证路线或无能力来源的事件预告；
- 普通事件缺源时显示“不可执行”；完整评分表缺源时不得显示总分、排名或多营地胜者；
- 行动分类合计必须等于团队总已消费行动，任何失败、协助、移动、维修或治疗行动不得从分母消失；
- 信标摧毁后显示终止状态并移除可维修操作；无名额或天线暂不可用只把连续广播归零，不误报为摧毁；
- 剩余 1 天疾病只结算一次最后效果，战后濒死者不会脱离救治队列，重伤检定缺源时不生成随机结果；
- 结算画面稳定时不反复重建内容或重复播报。
- 终局只出现一次结果；第 101/21 天的生产、治疗或广播不能改变胜负。
