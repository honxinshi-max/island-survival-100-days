# 《荒岛生存：百日余生》规则澄清包 V1.3.1（可执行性草案）

## 0. 身份、优先级与边界

- 基线：`游戏设计.md` 中逐字保留的 V1.2 权威稿，以及其上方的 V1.3 大漏洞修订草案。
- 优先级：本文件只在明确列出的事项上覆盖 V1.2 和 V1.3 草案；未列出的规则继续沿用 V1.2。尚未入库的 V1.1、职业卡、物品卡、生物卡、事件卡和地图表不由本文件推测补齐。
- 目标：让同一局面只有一种合法结算，不证明数值已经平衡。
- 适用范围：3—5 人、100 天完整版和 20 天压缩试玩版。

## 1. 本轮处理的不清晰点

| 编号 | 等级 | 不清晰点 | 不细化的后果 |
|---|---|---|---|
| C-01 | P1 | 项目何时算启动、失败前是否付材料、协助是否花行动 | 可无限免费试投，或把协助当免费加值 |
| C-02 | P1 | “高强度行动”“体力类检定”“休息”无统一标签 | 饥饿、脱水、伤势和疾病在不同桌上效果不同 |
| C-03 | P1 | 清晨伤病、救治、资源恢复和自动产出的先后未闭合 | 同一份资源可能在死亡前或死亡后出现，救治窗口不一致 |
| C-04 | P1 | 受损建筑的 1 点效果、二元能力、成本与容量如何处理 | “减半并向上取整”会让 1 点效果完全不衰减 |
| C-05 | P1 | 能源池的跨夜上限、设备名单和名额争用未定义 | 同一套发电/广播组合可被判为可运行或超限 |
| C-06 | P1 | 温室投入与产出的结算时点不明确 | 当天补水能否当天收获、停产是否补发会产生争议 |

| C-08 | P1 | “四账可胜性”只有原则，没有逐日判定算法 | 地图仍可能凭材料总量通过、却在时序上不可胜 |
| C-09 | P1 | “稳定产量”和可再生资源评分分母不闭合 | 可重复计算投入，或通过故意不探索提高分数 |
| C-10 | P2 | 驯兽上限下降和动物受伤后的处理时限不明确 | 超额动物可被永久保留，夜战受伤动物可能立即无解死亡 |
| C-11 | P2 | 事件整数权重的实体抽取法、同夜同级危机优先级不明确 | 不同主持人得到不同概率和不同危机 |

| C-14 | P1 | 终局夜在哪一步判胜、最终清晨伤病是否结算未定义 | 同一局可同时被判获救、全员死亡或继续进入第 101/21 天 |
| C-15 | P1 | 普通事件抽取日程、卡表、内部权重和抽后去向均缺源 | 主持人会自行决定何时抽、抽什么和是否放回 |
| C-16 | P1 | 危机选择前公开信息与最终结果标签缺失 | 玩家决策信息和“完全解决”计分可由主持人临时解释 |
| C-17 | P1 | 完整评分、总分、多营地排名和平局规则未入库 | 可用孤立分项拼出不同总分和胜者 |
| C-18 | P1 | 玩家/主持人/预知能力的信息公开边界未统一 | UI 可泄露隐藏点、未来事件或四账保证路线 |
| C-19 | P1 | 试玩比较上下文和触发指标未操作化 | 不同版本难度混算，调参门无法复算 |
| C-20 | P1 | 行动占比分母未覆盖全部已消费日常行动 | 相同行动日志可得到不同占比和相反调参决定 |

| C-23 | P1 | “重伤检定”缺少触发、目标值和结果表 | 主持人可自拟永久伤势或完全跳过 |
| C-24 | P1 | 信标行动账若按总进度合并取整会少计行动 | 多阶段不结转规则与四账行动数互相冲突 |

## 2. 项目声明、材料支付与协助（C-01）

### 2.1 项目启动

1. 项目执行者依次声明：项目或当前里程碑、执行者、目标值、行动成本、拟使用工具与至多两名协助者。
2. 独立项目在**第一次项目检定掷骰前**启动并支付全部材料；明确可独立完成的部件在该部件第一次检定掷骰前支付。研究样本与该项目的首次材料同时支付。
3. 材料或样本不足时不得检定。第一次检定即使失败并取得 0 进度，项目仍已启动；失败本身不自动返还材料、样本或行动。
4. 材料支付、行动消费、工具选择或随机结果一旦公开，不能把本次声明撤销为“未发生”。检定完整结算后，团队可以主动取消；即使本次结果为失败，取消仍按第 5—7 项的完成度和材料类别返还，不能把“失败不自动返还”解释为禁止取消返还。
5. 取消时的完成度为 `已应用进度 ÷ 项目总进度`，最高为 100%。可独立部件分别计算；求救信标是单一大型项目，以五段已应用进度合计除以本局信标总进度。
6. 完成度严格低于 50% 时，每种已支付的未加工基础材料返还 `floor（支付量 × 50%）`；恰好 50% 或更高不自动返还。研究样本和加工材料不返还，除非卡牌明示。
7. 取消后清除该项目全部进度与工程储备，只把第 6 项允许的返还移回库存；重新启动按新项目重新支付。

### 2.2 行动与协助

1. 执行者和协助者都在掷骰前支付行动。普通项目执行者支付 1 点；非专业替代的额外 1 点只由执行者支付。行动不足时不能声明该身份。
2. 每名协助者默认支付 1 点日常行动，必须与项目位于同一区域，且不能同时是本次执行者。能力另有明文时按能力覆盖。
3. 每次项目检定最多两名协助者；每名协助者的合法加值只加入一次，不另自产生进度。
4. 无论检定结果如何，执行者和协助者已支付的行动都不会返还。
5. 信标每次检定只处理声明时的当前里程碑；该段完成后的多余进度丢弃，不能跨段结转。

## 3. 行动标签与休息（C-02）

职业卡和行动卡后续应直接印出标签。在卡牌补齐前采用以下兜底表：

- **高强度行动**：狩猎、伐木、采矿、搬运、建造、维修、游泳，以及战斗中的攻击、保护和逃跑。
- **非高强度行动**：研究、室内制造、烹饪、治疗、整理物品、设备操作、基础检查、休息，以及战斗中的防守和使用物品。
- **体力类检定**：高强度行动附带的检定，以及卡牌明确标记“体力”的检定；没有检定的行动不会因“体力类检定 −1”额外产生检定。
- 卡牌明确标签优先于兜底表；事件临时改变标签时，必须在行动声明前公开。

“休息”统一为：非战斗、未被事件拘束的角色支付 1 点日常行动完成一次休息。休息本身不默认恢复生命、饱腹、水分或体温，只触发明确写有“完成一次休息”或“休息时”的效果。在运行篝火旁休息可按既有条款解除潮湿。

饱腹或水分为 0 时，角色仍可执行非高强度行动；高强度行动禁令不会被“每天最低 1 行动”解除。

## 4. 次日清晨、疾病到期与濒死出口（C-03、C-21、C-22、C-23）

夜间第 7 步扩展为以下固定次序：

1. 日数加 1；清空“上一日已使用”标记，重置当日设备名额和驯服动物的每日协助标记。
2. 依次结算流血、疾病每日生命损失、轻症复检、感染与传染。夜间第 6 步把剩余时间降至 0 的疾病先保持“待到期”，在本步骤执行最后一次每日效果后移除；明确写“立即结束疾病”的治疗已生效时不执行这次效果。被这些效果降至 0 的角色进入濒死，但在本清晨救治窗口关闭前不因后续被动生命损失重复死亡。
3. 应用已经产生的次日行动修正，计算每名清醒角色当日总行动。
4. 开启一次“清晨紧急救治窗口”。对象为所有尚未稳定的濒死者，不区分其来自战斗、灾害或被动状态。每名清醒、未被拘束且至少有 1 点当日行动的救治者最多救治一人；支付药品并把 1 点当日行动记为已经消费。濒死者不能救治他人，最低行动规则不返还该消费。
5. 窗口关闭时，所有仍未稳定或救治的濒死者死亡。
6. 按日程结算资源点恢复。
7. 结算清晨建筑投入与自动产出，包括温室。
8. 根据存活职业重新计算驯服上限，处理超额动物，再支付当日喂食。
9. 进入正常日间行动。

若事件明确写明“立即死亡”或新的攻击/灾害对濒死者造成伤害，仍按即时死亡规则处理，不等待清晨窗口。

- 战斗结束时仍未稳定的濒死者保留生命 0 和全部濒死标记；没有后续战斗轮时不凭空扣标记，也不会永久悬置，最近一次清晨按第 4—5 项处理。等待期间不取得激活机会，也不因另一场战斗的轮结束扣标记；若再次受到攻击或灾害伤害仍立即死亡。
- V1.1“重伤检定”的触发时点、目标值、结果区间和状态表均未入库，因此本版本停用该检定，主持人不得自拟。恢复该模块时必须一次性补齐四项字段及与稳定/治疗的先后关系。

## 5. 建筑耐久与“受损”能力（C-04）

### 5.1 状态判定

- **完好**：`2 × 当前耐久 > 最大耐久`。
- **受损**：`当前耐久 ≥ 1` 且 `2 × 当前耐久 ≤ 最大耐久`。
- **停机**：当前耐久为 0。

耐久不低于 0、不高于最大耐久。耐久 0 代表可维修的停机建筑；只有效果明确使用“摧毁”时才移除建筑并按该效果处理材料。

### 5.2 受损效果

1. 产量、伤害、治疗量、防御点和正向检定加值等可量化正向效果减半并**向下取整**，最低可为 0；值为 0 时只是该项能力不可用，不等于整栋建筑被摧毁。
2. 运行所需能源、燃料、水、材料和设备名额不减半。玩家必须在支付前看见受损后的产出；不允许先支付再改称“不运行”。
3. 仓储容量和居住人数在受损状态不减半，避免无规则地挤出物品或角色。进入停机时，既有物品和角色不会凭空消失：物品留在同一区域、可按正常行动取出但不能再存入；角色视为仍在该区域但不再获得住所防护，必须按无住所状态结算。建筑被摧毁时，再把内容物放入同区域公开区，并只结算摧毁效果明确写出的额外损失。
4. 科技前置、疾病等级解锁、自动取消灾害等二元能力在受损时默认不可用；设施卡只有明确标注“受损可用”时才能保留。
5. 停机建筑不能提供主动、被动或前置能力，但仍可被维修。
6. 求救信标不套用本节的普通产能规则；其启动、广播和待机继续使用专门耐久门槛。

## 6. 能源池与设备名额（C-05）

### 6.1 当日能源与跨夜储能

1. 发电产生的能源加入“当日可用能源”。同一天内可即时支付设备成本，能源不得为负。
2. 独立安装电池只决定跨夜保留量：`跨夜储能上限 = 6 × 可用独立电池数`。作为配方材料支付的内部电池不计入。
3. 夜间第 5 步全部设备、广播或待机成本结算后，执行：`保留能源 = min（剩余当日能源，跨夜储能上限）`；超出部分清零。没有独立电池时上限为 0。
4. 若电池在夜间第 1 步被摧毁，按第 5 步结算时仍可用的电池重新计算上限。

### 6.2 设备名单与占用

当前可见规则中的“设备”统一为：发电机、高级净水器、主动机械排水、支付能源进行自动攻击的自动防御设施，以及执行启动、广播或待机的求救信标。普通温室、被动排水、防御设施的被动防御点、独立电池和个人装备不占设备名额，除非卡牌明确带有“设备”标签。

1. 每个设备在首次成功启动、生产或支付运行成本前检查名额；没有空余名额时，本次操作不能执行，也不支付能源或原料。
2. 同一设备同一天多次合法运行仍只占 1 个名额；不同设备分别占用。设备一旦成功运行，名额保留至次日清晨，普通关机不能释放。
3. 发电机发电占 1 个名额。信标同一天既启动又广播时合计占 1 个名额。
4. 自动防御设施只保留被动防御点时不占名额；主动机械排水只有在实际启动时占名额。
5. 上限在当日下降时，团队立即公开选择不超过新上限的已登记设备继续保留运行资格；其余设备关闭。已经结算的效果不倒退，被关闭设备当日不能再次运行。

## 7. 温室生产窗口（C-06）

1. 温室完工当天不立即产出，最早在下一个清晨建筑产出步骤运行。
2. 每座可运行温室在该步骤先选择作物，再支付安全淡水 1；支付后同一清晨立即产出。完好温室产野菜 2 或草药 1。
3. 受损温室按受损建筑规则结算：野菜 1；草药基础产量 1 减半向下取整为 0，因此受损时不能选择草药。
4. 未支付水时，本次生产直接跳过；不产生欠账、不累积“补发产量”，恢复供水后在下一次清晨窗口正常运行。
5. 温室不默认附带种子、免费首批作物或能源成本。未来加入种子系统时必须由设施卡或模式规则明示。

## 8. 求救信标状态机（C-07）

信标必须且只处于以下一种状态：`未完工`、`待启动`、`已启动（连续广播 0/1/2 夜）`、`已锁定`、`停机`、`已摧毁`。

主线为：

`未完工 → 待启动 → 已启动（0/1/2 夜）→ 已锁定`

- 任一已完工且未摧毁状态在耐久降至 0 或效果明示“关机/必须重启”时进入`停机`；修复并解除可恢复阻断后只回到`待启动`。
- 效果明示“摧毁”时进入终止状态`已摧毁`，移除信标并按 C-04 处理内容物；不能用普通维修从该状态返回。

1. 五段完成后进入“待启动”。白天声明启动时，信标必须未被屏蔽、耐久严格高于最大耐久 50%、有设备名额并支付 1 能源；成功后进入“已启动（0 夜）”。同夜广播仍另付 3 能源。
2. 已启动信标每夜在事件与战斗后检查耐久、天线、基础检查、屏蔽、设备名额和 3 能源。全部满足则连续广播数 +1；达到 3 后进入已锁定。
3. 广播因能源不足、基础检查缺席、临时屏蔽、天线暂时不可用、没有设备名额或耐久降至 1—50% 而无效时，连续数归 0，但保持“已启动”；条件恢复后无需重复支付启动能源，除非效果明示必须重启。
4. 耐久降至 0 或效果明示“关机/必须重启”时，连续数归 0 并进入停机；修复且解除阻断后回到待启动，必须再次支付 1 能源启动。被摧毁时直接进入已摧毁，不经过可修复停机。
5. 已锁定后，每个后续夜晚必须有信标设备名额、可用天线、未被屏蔽并支付 1 能源待机。任一可恢复条件不满足时丢失锁定并回到“已启动（0 夜）”；耐久 0 或明示关机进入停机；被摧毁进入已摧毁。
6. 每夜基础检查需要一名当天已到达信标区域、清醒、未濒死、未昏迷且未隔离的角色；检查本身不消耗行动。没有合法执行者时该夜广播无效。
7. 系统必须显示按当前连续数重新计算的最迟有效广播日，不能只显示第一次启动期限。

## 9. 开局四账可胜性算法（C-08）

地图生成后，选择至少一条具体的标准胜利路线，并从第 1 天排到终局夜。标准路线按开局 3—5 名角色全部存活、不依赖随机奖励或职业爆发来核算；四账必须同时通过：

### 9.1 材料账

对路线中的每种不可再生材料，在完成合法替代和加工换算后验证：

`保证可得量 ≥ 路线需求量 + ceil（路线需求量 × 10%）`

1. 路线需求量包含研究样本、建造材料、内部电池、加工燃料、终局前必须消耗的维修与运行投入；已经支付进项目或配方的物品不能再计作库存、独立储能或另一配方的输入。
2. 不同材料分别验算，不能用一种材料的富余抵消另一种材料的短缺。随机事件、非保证掉落和玩家自创物品不计入。

### 9.2 行动与依赖账

1. 用普通成功的 2 点项目进度和表内确定性采集下限编制逐日计划；不计超额成功、职业爆发或随机奖励。
2. 多阶段项目不能把总进度合并后取整。信标基准成功建造行动固定为 `Σceil（各段进度 ÷ 2）`；完整版 3/4/5 人分别为 15/15/20 次，20 天版 3/4/5 人均为 5 次。20 天表只证明材料和进度点已缩放，不得宣称基准成功行动数随人数变化。
3. 计划覆盖第 1 天至终局夜，包含移动、采集、加工、研究、建造、协助、必要维修、食水取得与处理、发电、启动、广播保障和其他胜利必需操作；不能在信标启动日提前停止记账。
4. 所有研究、设施、材料、位置和设备名额前置必须在使用前完成；同一角色的同一行动不能重复记账，同一份产出也不能同时满足两个消耗。
5. 全周期团队基础可用行动必须满足：

`可用行动 ≥ 计划行动 + ceil（计划行动 × 15%）`

### 9.3 全周期生存账

1. 第 1—3 夜是硬门：每夜结算前必须有保证可达的安全食物与安全淡水满足全部开局人口的基础消耗；不能依赖尚未完成的设施、随机事件或未处理资源。
2. 第 4 夜至终局夜逐夜证明同一人口的食水消耗可由保证库存、确定性采集、计划恢复和已建生产设施承担。取得、移动、处理、燃料与设备名额均必须同步进入其他三账。
3. 同一份食物、淡水、燃料或原料只能分配一次。某日短缺不能用后一天的产出倒填；允许的跨日库存必须满足保质期与仓储规则。

### 9.4 能源与可达账

1. 设模式终局日为 `T`（完整版 100，试玩版 20），计划启动日为 `d`。必须先满足 `d ≤ T − 2`；否则即使能源充足也无法完成三夜广播，能源账直接失败。满足期限时，信标最低能源为：

`1（启动） + 9（三夜广播） + max（0，T − d − 2）（锁定后的待机）`

2. 另加同一路线中必须运行的发电、净水、防御等设备成本，并从第 1 天至终局夜逐日验证发电输入、电池跨夜容量、当日设备名额及已承诺能源的支付顺序。
3. 所有关键资源、设施和信标区域必须按计划在使用日前可达；需要非保证随机事件或不可重复随机开路的路线不算保证可达。
4. 任一账失败时只重生成相关点位或路线，并重新跑完整四账，不得用另一账的富余抵消。

只要 V1.1、完整高级材料配方、第一百零七条信标全部前置、普通建筑 20 天材料系数、卡表或地图表中有一个路线必需字段缺失，对应账就标记“待确认”，整张地图不得标为“四账通过”。在这些字段回填前，也不得发布“完整依赖拓扑已闭合”“发电—广播能源账通过”或“普通建筑 20 天材料缩放已确定”的结论。四账只是标准结果下的名义可胜性，不是胜率保证；真实平衡仍由试玩反馈决定。

## 10. 评分口径（C-09）

### 10.1 可再生资源分母

- 分母：地图生成时本局全部可再生资源点数，包括尚未发现的点位；主持或系统在终局统一读取，玩家不必提前知道隐藏数量。
- 分子：终局已发现、未被永久摧毁且仍保有自然恢复规则的可再生资源点。当前储量为 0 但会在后续计划恢复日恢复的点位仍可计入。
- `可再生资源分 = 25 × 分子 ÷ 分母`；分母为 0 时记 0。
- 另报 `探索率 = 已发现全部资源点数 ÷ 地图生成全部资源点数`，用于区分保护资源和根本未探索。

### 10.2 稳定饮食与饮水产量

投影固定为终局状态后的 `T+1、T+2、T+3`。从终局完整快照开始，逐日推进正常清晨资源恢复、建筑投入与产出、角色日常行动、设备名额、能源/燃料成本和食水消费；不新增探索，不抽事件，不进入战斗，不计非保证掉落。

1. 玩家先为三天生产计划分配终局库存和每日行动；同一份原料、能源、设备名额或行动只能分配一次。已分配给生产的终局库存不能同时计入“三天储备”。
2. 每日稳定饮水恢复点取三天中**最低一天**可合法产出的安全水分恢复点；食物同理取最低一天饱腹恢复点。
3. 投影期间按既有日程推进资源恢复；投影生成的食物、淡水和副产物只用于产量诊断，不回填终局“三天储备”。
4. 本节“当前人口”统一指终局健康闭合后生命高于 0 且非濒死的角色数；濒死、死亡或已经离队者不进入需求分母。
5. 每名角色的投影行动按终局可持续状态计算；若基础行动、配方、设施投入或恢复日程有一项缺源，该分项标记“待确认”，不能给出分数。
6. 当前人口为 0 时，幸存者状态与全部资源可持续性分直接记 0，不执行除法。

### 10.3 完整评分与多营地边界（C-17）

1. V1.1 完整评分表、全部分项上限、总分上限、多营地排名和平局规则未入库前，本仓库只允许逐项记录当前已定义的诊断值；不得把它们相加为“完整总分”，不得据此排名或宣布多营地胜者。
2. `求救得分 170` 只是 V1.2 附录中的孤立补充，不能单独证明完整评分系统存在。
3. 当前可执行的标准模式只按 C-14 的合作救援二元条件判胜负，评分不覆盖或改写救援结果。
4. 启用完整评分或多营地模式前，同一规范页必须列齐：每个分项公式与上限、总分上限、各层取整时点、零分母结果、危机结果标签、二元胜负与分数关系，以及完全同分时的处理。缺少任一项时该模式标记“不可执行”。

## 11. 驯服动物（C-10）

1. 有驯兽师时维持上限为最高驯兽师等级 +1；无驯兽师时维持上限为 1，但不能新增驯服动物。
2. 每个清晨在角色死亡、濒死、离队和职业变化结算后重算上限。团队公开选择超额动物离开；离开不产生肉、材料或其他掉落，之后即使上限恢复也不会自动返回。
3. 超额处理后，为保留动物支付当日食物。当天新驯服的动物从下一个清晨开始支付日常食物。
4. 战斗型动物生命降至 0 后进入“受伤”状态：不能协助或战斗，但仍占维持上限。团队必须在下一次夜间第 1 步前支付其可接受食物 1，并由一名角色支付 1 日常行动完成治疗；两项缺一则该动物死亡。卡牌写明“立即死亡”时优先。

## 12. 事件、危机与主持一致性（C-11、C-15、C-16）

### 12.1 事件源闭合门（C-15）

1. 当前仓库缺少 V1.1 普通事件抽取日程、六类完整标识、类别内事件清单和事件卡，因此普通随机事件模块标记为“缺源、不可执行”。主持人不得自行决定抽取频率、补写事件、猜测权重或选择是否放回。
2. 启用普通事件前，模式表必须列明每个抽取窗口与数量；每张事件卡必须有唯一稳定 ID、所属类别、基础整数权重、类别内权重、抽后去向（放回/弃置/冷却）、可重复次数及重新入池条件。任一字段缺失的卡不得入池。
3. 模块不可执行时，玩家界面显示“普通事件：缺源停用”，而不是“无事件”或主持人提示。危机只有在其触发日程和卡牌字段完整时才可独立启用。

### 12.2 整数权重

1. 每类事件基础整数权重为 4；+25% 记 +1，+50% 记 +2，−25% 记 −1，−50% 记 −2。不同来源相加，同名来源不重复；最终权重最低为 0。
2. 桌面版按最终权重放入同名类别标记，均匀抽 1 枚；数字版在 `1…总权重` 上均匀取整数并按累计区间选类。抽后是否放回必须由事件卡字段决定，不能一律假定放回。
3. 选出类别后，再按卡牌的类别内整数权重抽具体事件；“多雨”等只修改明确写出的内部子权重。总权重为 0 或缺少内部权重时配置无效，不进行抽取。

### 12.3 大型危机候选表

1. 每夜第 1 步在自动防御能源承诺之后建立“大型危机候选表”，纳入阶段、周期、事件触发及其他全部来源。只有字段完整的候选才能进入。
2. 先只保留最高等级。等级相同时按卡牌明示优先级；未明示时默认优先级为阶段 3、周期 2、事件触发 1，其他来源必须明示。仍并列时按公开稳定 ID 升序保留第一项，不再临时随机。缺少等级、来源、必要优先级或稳定 ID 时配置无效。
3. 未保留危机直接压制：不顺延、不补抽、不进入危机计分分母。普通事件若明示“升级为大型危机”，该牌离开普通事件槽后进入候选表，不重复作为普通事件结算。
4. 第 1 步固定按“普通事件（若模块可用）→应用白天已取得的危机预防→保留危机的应对阶段→止损阶段→其余未被事件包含的营地防御战”处理，卡牌明示替换时除外。

### 12.4 选择前公开与结果标签（C-16）

1. 玩家选择危机方案前，必须公开：危机 ID、等级、来源、影响范围、截止时点、全部合法选项、各自成本、目标值，以及超额成功/成功/部分成功/失败/放弃的后果。只隐藏规则明确保留且尚未产生的随机结果。
2. 每个最终分支必须带且只带一个标签：`完全解决`、`部分解决`、`未解决`。预防阶段在应对前消除全部损失时记“完全解决”；其他应对或止损结果只按卡牌标签记录，主持人不得由叙事临时改级。
3. 缺少公开字段或最终标签的危机卡不得进入候选表。危机结算后，最终权重、候选表、压制原因、抽取/决胜结果和最终标签全部进入公开日志。

## 13. 资源恢复（C-12）

在每个计划恢复日，对该点位执行：

`恢复后储量 = min（初始储量，当前储量 + ceil（初始储量 × 20%））`

当前储量为 0 也照常恢复，不跳过、不延后；“枯竭”在 V1.3.1 中只表示当前不可采集，不再附带额外恢复惩罚。恢复在清晨完成后，当天日间即可前往采集。

## 14. 战斗时点闭合（C-13）

1. **激活机会**是交替行动顺序轮到该单位的时点；即使该单位因眩晕、跳过、拘束或其他效果不能行动，该时点仍然发生。
2. 防守从声明并支付战斗行动后生效，在该单位下一次激活机会开始时、处理跳过或眩晕之前结束；若单位先离开战斗序列或战斗结束，防守立即结束。任何防守最迟不超过下一战斗轮结束。
3. 每次攻击最多发生一次保护转移。保护必须在攻击检定前声明；保护者必须与原目标同区、清醒、非濒死、可成为该攻击的合法目标，且不能保护自己。若 V1.1 或卡牌没有更具体成本，默认消耗保护者本轮尚未使用的一次战斗行动。
4. 转移后以保护者的防御、护甲、状态和位置结算；同一次攻击不能再由第三者保护，保护者也不能对该攻击再次触发保护。
5. 角色进入濒死的当轮结束时不移除濒死标记；从其后的每个完整战斗轮结束才移除 1 枚。稳定会清除全部濒死标记；稳定后再次降至 0 时重新放置 2 枚。

## 15. 终局夜与结束条件（C-14）

1. 模式终局日 `T` 为完整版第 100 夜、试玩版第 20 夜。该夜先完整执行夜间第 1—6 步，再执行一次“终局健康闭合”：按 C-03 第 2—5 项结算流血、疾病、轻症、感染、次日行动计算、紧急救治和未救治死亡。
2. 终局健康闭合不打开第 `T+1` 天，不结算资源恢复、建筑产出、动物喂食或新的日间行动；紧急救治所消费的行动只用于判断救治者是否有资格，结算后不再产生可用行动。
3. 健康闭合后按以下优先级只判定一次：
   - 没有生命高于 0 且非濒死的角色：`全员死亡，救援失败`，即使信标已锁定也不获救；
   - 至少一名合格幸存者且信标仍为已锁定：`救援成功`；
   - 至少一名合格幸存者但信标未锁定：`期限届满，救援失败`。
4. 终局前若全体角色在同一效果完整结算后均已死亡，标准合作模式立即结束，不再抽事件、恢复资源或产生建筑产出。
5. 终局判定后只进入结算与反馈记录；不得再用第 `T+1` 天的生产、修复、广播或治疗改变结果。

## 16. 信息公开与试玩测量（C-18、C-19、C-20）

### 16.1 字段级公开矩阵（C-18）

| 字段 | 默认可见性 | 转为公开的时点 |
|---|---|---|
| 规则版本、模式、难度、玩家数与职业、当前天数、已揭示岛屿特性 | 开局公开 | 始终公开 |
| 已发现区域、资源点位置、当前/初始储量、恢复类别与下次恢复日 | 玩家发现后公开 | 发现时 |
| 未发现点位置与储量、全图评分分母、四账保证路线的隐藏来源 | 主持人/系统专用 | 终局只公开汇总分母和审计结果，不反向泄露未探索详情 |
| 未来事件身份、顺序与精确结果 | 默认隐藏 | 仅由明确预知能力按其字段范围公开 |
| 事件/危机最终权重、候选表、抽取结果、结果标签与结算日志 | 结算前按规则部分公开 | 正式揭示或结算后全部公开 |

1. 事件预告必须显示来源能力、允许精度和失效时点；没有合法来源时显示“无公开预告”，主持人不得自由暗示。
2. 四账的玩家视图只显示“通过/无效/待确认”及非泄密的缺口类别；完整点位、保证路线和隐藏库存只在主持审计视图保存。
3. 事件模块因缺源停用时必须明确显示“不可执行”，不能伪装成“今晚无事件”。

### 16.2 可比较试玩样本与指标（C-19）

1. 每局必须记录：规则版本、模式、难度、人数、职业组合、地图配置 ID/随机种子、已公开岛屿特性、普通事件 ID 序列、危机 ID/等级/来源/最终标签，以及终局结果。
2. 胜率和调参门只在规则版本、模式、难度相同的样本组内计算；不足约定样本数时只报告原始结果，不触发调参。人数与职业继续作为组内解释变量单列。
3. “首次稳定饮水/食物日”使用与 C-09 相同的连续三日无随机投影：首个能让三天每天覆盖 100% 当时存活人口需求的日期；第三天中断则不得提前记为稳定。
4. “阶段”和“决战期”必须由模式表在开局前给出日数边界；当前缺少边界时，相关反馈门停用。
5. “不可逆崩溃”必须保存当时快照，并证明不存在合法的三日生存路线；“职业不可替代”必须记录因缺少该职业而被规则阻断、且专业替代也无法执行的具体节点；“设备取舍”必须记录同一支付窗口中至少两个合法设备竞争不足能源或名额的实际选择。
6. “没有真实选择”记录 0 个或更多时刻，不强迫每局填写 3 个；每项至少包含状态、公开选项、玩家认为可行的选项、实际选择和即时后果。

### 16.3 行动分类与分母（C-20）

1. 每次已消费的日常行动必须且只能归入一个标签：移动、采集、加工/制造、研究、建造、维修/维护、治疗/休息、设备操作、战斗、协助、其他。
2. 执行者按主要行动分类；协助者所消费的行动归“协助”。失败行动、预支救治和已经支付后被中断的行动仍进入分母。
3. `团队总已消费行动 = 全部标签行动数之和`；行动占比统一为 `该标签行动数 ÷ 团队总已消费行动`。无法分类时记“其他”，不得从分母消失。
4. 免费基础检查和不消耗日常行动的战斗内动作不进入该分母；若卡牌明确把战斗动作改为消耗日常行动，则按“战斗”计入。
5. 团队总已消费行动为 0 时，各占比记 0，并标记该局日志无有效行动样本。

## 17. 纸面规则验收矩阵

以下案例只检验规则是否得到唯一结算，不宣称数值已经平衡：

| 场景 | 唯一预期结果 |
|---|---|
| 普通检定差值为 −2/−1/0/+2/+3 | 依次为失败/部分成功/成功/成功/超额成功；全部整数差值只落入一个区间 |
| 最大耐久 20，当前为 11/10/1/0 | 依次为完好/受损/受损/停机；受损基础产量 1 变为 0 |
| 仓库耐久降至 0 时内有物品，住所耐久降至 0 时仍有角色 | 物品留在同区且只能取出；角色留在该区但按无住所结算；均不凭空损失或继续取得建筑防护 |
| 初始储量 8、当前 0，来到计划恢复日 | 恢复 2，储量变为 2，不跳过恢复 |
| 夜间设备结算后剩余能源 14，有 2 块独立电池/无独立电池 | 分别跨夜保留 12/0 |
| 20 天 4 人信标塔架还差 2，难度 7 超额成功得 3 进度 | 塔架完成，1 进度丢弃；天线仍需新的难度 9 行动 |

| 当前只有孤立的求救 170 和资源诊断分，没有完整评分总表 | 可记录已定义诊断值，但不得计算总分、排名或多营地胜者 |
